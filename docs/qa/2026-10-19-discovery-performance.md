# Warm Discovery verification — 2026-10-19

The existing signed-out district endpoint meets the roadmap's 500 ms warm
target in this local development check. This is not a production latency or
browser-rendering claim. No blocked source, account acceptance flow or
production deployment was invoked.

## Measured paths

Each region selection received one warm-up request followed by three timed
requests against the configured Neon database and current promoted metrics.
The source rate was PMMS. The test profile is synthetic and no profile values,
credentials, request URLs or response bodies are retained in the reports.

The data path includes rate resolution, the actual district SQL, purchasing
power and percentile scoring. The separate HTTP check called the existing
`getDistrictPurchasingPower` RPC through the running app, including framework
serialization and response decoding. It used the installed serialization
codec, the RPC metadata generated by Vite, and normal same-origin request
headers. Every timed HTTP request returned 200 and
`Cache-Control: private, max-age=60`, without a session or cookies.

These are separate runs, not paired speedup measurements. They exclude
commute/geocoding calls, narrative generation and browser rendering. They are
nine warm samples per path, not a load test, cold-start bound or guarantee
across networks. Repeat after GVI promotion and the final archetype rebuild;
this check does not substitute for those data gates.

## Outage handling corrected

Successful mortgage-rate observations retain their existing 24-hour cache.
Previously, an unavailable source returned the documented fallback but did
not cache it: every subsequent request could wait through the same upstream
timeout. The fallback is now reused for one minute before retrying. Its value,
`fallback` label and absent observation date are preserved. A regression test
proves reuse during the retry window and recovery to PMMS at expiry; no live
source outage is induced. Concurrent success/failure regressions also prove
that a valid PMMS observation wins over a fallback regardless of which request
started first.

## Repeating the data-path check

With the intended `DATABASE_URL` supplied securely to the process:

```sh
cd app
GROUNDTRUTH_DISCOVERY_PERFORMANCE=1 npm test -- src/lib/finance/discovery-performance.integration.test.ts
```

The test is read-only and skipped during ordinary `npm test`. It requires each
of its nine warm samples to remain below 500 ms and writes only timing, count,
source-label and scope evidence. It does not load `.env.local` automatically.
